# S3 "The arena" — app workstream (W1) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** S3's app half — you steer Wander through the Valus arena: a character controller, a game-style third-person camera (cursor never captured), and a scene-composition loader that assembles the arena from a data-mined manifest.

**Architecture:** The app gains a line-oriented scene manifest (instances + spawn), a composed-scene loader that bakes per-instance transforms into the existing per-mesh model-matrix path, a rasterized ground heightmap for ground-following, and a player controller + follow camera extending the existing input loop. Acceptance follows the s1 pattern (script + measured numbers + screenshots).

**Tech Stack:** C++20 · SDL3 (windowed, no capture) · SDL_GPU/Metal · existing `math3d` · doctest · bash 3.2.

**Spec:** `docs/superpowers/specs/2026-10-18-s3-arena-design.md` — workstream W1, §1's pinned calls (extent, movement model, animation scope) · inherits `docs/superpowers/specs/2026-10-16-sdl-rebuild-design.md` and `2026-10-18-first-playable-design.md`.

## Global Constraints

- `SOTC_LIB` (or `--library`) is required; fail loudly, never skip (tests exit non-zero without it).
- Windowed; cursor never captured (`SDL_HINT_MOUSE_AUTO_CAPTURE=0` stays).
- Shaders are runtime MSL strings (no metallib).
- Movement model (spec §1): **ground-follow + arena-edge clamp; no wall/prop collision**.
- Animation scope (spec §1): S2's delivered clip + labeled stand-in; **no locomotion clip selection** in this plan.
- Build/test: `cmake -S app -B app/build && cmake --build app/build -j`; `ctest --test-dir app/build --output-on-failure`. New sources and tests are appended to **both** explicit lists in `app/CMakeLists.txt` (renderer.cpp is not linked into tests).
- Scripts stay bash 3.2 compatible; game assets and derived outputs are never committed; small typed commits.
- **The manifest is the W1↔W2 interface**: schema committed at `docs/notes/scene-manifest.md`; W2 emits the arena manifest to `out/re/stage/valus.manifest` (gitignored).

## Review Focus

1. A manifest naming a missing/unloadable glb → one-line error naming the file and line, non-zero exit — never a crash.
2. Spawn over a heightmap hole (no ground) or outside bounds → defined fallback (nearest valid height; clamp to bounds), never NaN or a teleport.
3. Frame-time spikes (dt ≫ 16 ms) → movement stays clamped and continuous; no tunneling past the edge clamp.
4. NaN/inf/malformed numbers in a manifest → parse fails loudly with the line number.
5. Walking to the arena edge and the heightmap border → position clamps, camera stays sane, no falling off.

### Task W1.1: Scene manifest format + parser

**Files:**
- Create: `app/src/manifest.h`, `app/src/manifest.cpp`
- Test: `app/tests/test_manifest.cpp`
- Create: `docs/notes/scene-manifest.md` (the committed schema — W2 conforms to it)
- Modify: `app/CMakeLists.txt`

**Interfaces:**
- Produces:
  - `struct ManifestInstance { std::string glbRelPath; Vec3 position; Quat rotation; Vec3 scale; };`
  - `struct SceneManifest { std::vector<ManifestInstance> instances; Vec3 spawnPosition; float spawnYawDeg; bool hasSpawn; };`
  - `SceneManifest parse_manifest(const std::filesystem::path& path);` — throws `std::runtime_error` formatted `<file>:<line>: <reason>` on any malformed line.
- Schema (line-oriented, `#` comments, blank lines skipped; numbers are strict full-string finite floats):
  - `instance <glbRelPath> <px> <py> <pz> <qx> <qy> <qz> <qw> <sx> <sy> <sz>`
  - `spawn <px> <py> <pz> <yawDeg>`
  - Unknown directives fail loudly.

- [ ] **Step 1: Write the failing tests**

Cases: (a) a manifest with one `instance` + one `spawn` parses with exact values (position/rotation/scale/spawn/yaw); (b) comments and blank lines are skipped; (c) no `spawn` → `hasSpawn == false`, `spawnPosition == {0,0,0}`; (d) wrong token count → throws, message contains `:3:` for a line-3 error; (e) `nan`/`inf` in any numeric field → throws with the line number; (f) unknown directive `foo ...` → throws naming the directive. Use fixture text written to a temp path (follow `test_asset_io.cpp`'s temp-file pattern).

- [ ] **Step 2: Run tests to verify they fail**

Run: `cmake -S app -B app/build && cmake --build app/build -j && ctest --test-dir app/build --output-on-failure -R unit_tests`
Expected: FAIL — `manifest.h` not found / linker error.

- [ ] **Step 3: Implement `parse_manifest`**

`std::ifstream` line loop; split on whitespace; per-directive token counts; strict float parse (whole token consumed, `std::isfinite`); build the structs; on error throw with `path.string() + ":" + lineNumber`.

- [ ] **Step 4: Run tests to verify they pass**

Run: `ctest --test-dir app/build --output-on-failure -R unit_tests`
Expected: PASS (all cases).

- [ ] **Step 5: Write `docs/notes/scene-manifest.md`** — the schema exactly as above + the W2 output path `out/re/stage/valus.manifest` + a 3-line example.

- [ ] **Step 6: Commit**


### Task W1.3: Ground heightmap

**Files:**
- Create: `app/src/heightmap.h`, `app/src/heightmap.cpp`
- Test: `app/tests/test_heightmap.cpp`
- Modify: `app/CMakeLists.txt`

**Interfaces:**
- Produces:
  - `struct Heightmap { float cellSize; int width, height; std::vector<float> heights; Vec3 boundsMin, boundsMax; };`
  - `Heightmap build_heightmap(const Scene& scene, float cellSize);` — rasterizes every mesh triangle into the grid (per-cell max-Y; empty cells stay NaN); throws `std::runtime_error("no meshes")` on an empty scene.
  - `float heightmap_sample(const Heightmap&, Vec3 p);` — bilinear over valid cells; falls back to the nearest valid cell's value; clamps to `boundsMin/boundsMax`.
  - `bool heightmap_in_bounds(const Heightmap&, Vec3 p);`

- [ ] **Step 1: Write the failing tests** — a fixture scene with one triangle at y=3 over `[0,10]²`: inside sample ≈ 3; a two-triangle ramp → bilinear between the two heights at the midpoint; outside bounds clamps to the edge value; a hole cell (gap between two triangles) samples the nearest valid value; empty scene throws.

- [ ] **Step 2: Run to verify FAIL.**

- [ ] **Step 3: Implement** — bounds from the scene, grid dims = ceil(extent/cellSize)+1; per triangle: bounding-box cells, rasterize by triangle-plane Y at cell centers; `heightmap_sample` scans 2×2 cells, uses the nearest valid one if any is NaN.

- [ ] **Step 4: Run to verify PASS.**

- [ ] **Step 5: Commit**

```bash
git add app/src/heightmap.h app/src/heightmap.cpp app/tests/test_heightmap.cpp app/CMakeLists.txt
git commit -m "feat(app): rasterized ground heightmap"
```

### Task W1.4: Player controller + follow camera + CLI + selftest

**Files:**
- Create: `app/src/player.h`, `app/src/player.cpp`
- Test: `app/tests/test_player.cpp`
- Modify: `app/src/camera.h`, `app/src/camera.cpp` (follow mode), `app/src/app.h`, `app/src/app.cpp`, `app/src/main.cpp`, `app/CMakeLists.txt`

**Interfaces:**
- Produces:
  - `struct PlayerInput { bool forward, back, left, right, run; };`
  - `struct PlayerState { Vec3 position; float yawDeg; };`
  - `void player_update(PlayerState&, const PlayerInput&, float dtSeconds, const Heightmap&, float cameraYawDeg);` — movement is camera-relative; walk `2.2 m/s`, run (Shift) `5.0 m/s`; yaw turns toward the movement direction at `540°/s`; `dt` is clamped to ≤ `0.05 s`; `position.y = heightmap_sample`; XZ clamped to the heightmap bounds inset by `0.5 m`.
  - `struct CameraFollow { float yawOffsetDeg, pitchOffsetDeg, distance; };` (+ `float followBlend` internal) — `void camera_follow(Camera&, CameraFollow&, Vec3 playerPos, float playerYawDeg, float dragDxPixels, float dragDyPixels, float wheelDelta, bool moving, float dtSeconds);` — target yaw = `playerYawDeg + yawOffsetDeg`, target position = playerPos + `(0, 1.4, 0)`; drag adds to the offsets; when `moving`, offsets decay toward 0 at `1.5 s⁻¹`; distance starts `4.5 m`, wheel zooms within `[2, 12]`; pitch clamped ±60°.
  - CLI: `--manifest PATH` (requires `--model` as the player glb; exit 2 otherwise), `--s3-selftest` — loads the composed scene, spawns (manifest spawn or bounds centre), simulates `240` fixed `1/60 s` frames of `forward+run`, renders one frame, prints `s3-status instances=<N> spawn=<x,y,z> pos=<x,y,z> ground=<ok|none> frames=240`, exits 0.
- Input mapping (interactive loop): `W/A/S/D` scancodes + `LShift`; drag → `camera_follow` offsets (existing MOUSE_MOTION path); wheel → distance. Existing keys (`F`, `Space`, `R`, `[`, `]`, Escape) stay.

- [ ] **Step 1: Write the failing tests** — with a flat heightmap at y=0 and camera yaw 0: forward input moves +Z (camera-relative convention pinned in code) at walk speed × dt; run speed with `run=true`; `dt=1.0` advances ≤ `5.0×0.05`; clamp: starting at the bounds edge minus `0.4`, forward stops at the inset; y follows `heightmap_sample` (use a ramp fixture); `player_update` never produces NaN with dt=0. Camera: `camera_follow` with `moving=false` keeps offsets; with `moving=true` decays them; drag changes offsets by the pixel deltas × sensitivity; distance clamps `[2,12]`.

- [ ] **Step 2: Run to verify FAIL.**

- [ ] **Step 3: Implement** — as specified; movement basis: forward = `(sin(yaw), 0, cos(yaw))` of the camera yaw (pin the exact convention in a comment; tests use it).

- [ ] **Step 4: Run to verify PASS; build the viewer; run the interactive smoke manually once** (`--manifest` with a hand-written 2-instance test manifest under `out/`): window opens, drag looks (cursor stays free), WASD walks, Shift runs, edge clamps. This is a builder check, not acceptance.

- [ ] **Step 5: Commit**

```bash
git add app/src/player.h app/src/player.cpp app/src/camera.h app/src/camera.cpp app/src/app.h app/src/app.cpp app/src/main.cpp app/tests/test_player.cpp app/CMakeLists.txt
```
