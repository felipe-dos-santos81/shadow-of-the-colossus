# S5 — The Sound of the Forbidden Land Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Decode the game's own SXDF/ATRAC9 audio at build time and play music, ambience, and a curated combat slice from the existing simulation through SDL3, proven by a deterministic headless mixdown and the user's ear.

**Architecture:** A new `bp-convert audio` verb parses the `SXDF` banks and `.sxd1`/`.sxd2` pairs, carves the selected AT9 records, decodes them to 48 kHz PCM WAV, and writes a line-based `audio.manifest`. The C++ app loads only that manifest + WAVs into an `AudioEngine` (software mixer → one `SDL_AudioStream`), fed by an `SfxEvent` queue translated from `StepEvents` and the encounter events. Two hard gates precede the code: a decode proof and a resident-bank attribution proof.

**Tech Stack:** .NET 10 (xUnit), C++20, SDL3 3.4.18 (core audio API, `disk` driver), doctest, bash 3.2, Python 3 for the RE gate scripts.

**Spec:** `docs/superpowers/specs/2026-10-21-s5-audio-design.md`

## Global Constraints

- **SDL3 3.4.18 + SDL_GPU/Metal**, C++20, Apple Silicon; **windowed**; **the cursor is never captured or locked**.
- Offline-first: the runtime reads only the converted manifest/WAV; it never parses `.sxd`/`.sxd2`.
- Assets and derived audio are **never committed**; `out/` is gitignored. Personal use, no redistribution.
- Decode at build time only: VGAudio (MIT) or an FFmpeg (LGPL) subprocess; neither ships in the runtime.
- .NET 10 converter; tests fail fast without `SOTC_GAME_ROOT` / `SOTC_LIB`; bash 3.2; typed commits; **≤4 concurrent agents**.
- The S4.2/S4.1/S4/S3 manifests and scripts are **not modified**; the S4.2 script is only invoked.
- Acceptance runs under `caffeinate -dimsu`; never two acceptances concurrently.
- The curated map is the only audio shipped this pass; the full 1.9 GB inventory is out of scope.

## Review Focus

The spec implies these failure modes; each has a test in the task that owns the code:

1. **A decode that is silent, noise, or the wrong duration** — Task 0's gate asserts 48 kHz, the declared duration, RMS, and peak before any code is written; Task 3 repeats it for a curated entry.
2. **A wrong-but-plausible cue** (a name mapped to the wrong wave) — Task 1's attribution table records index/method/confidence, and Task 6's user walk is the identity check; the scripted checks cannot catch this.
3. **The runtime starts parsing SXDF** — Task 3's manifest is the only input the app reads; Task 4/5 never open a `.sxd`.
4. **The audio layer changes the S4.2 timeline** — Task 5 asserts the `s42-*` lines are byte-identical with audio off, and Task 6 runs the frozen S4.2 acceptance.
5. **A missing audio device breaks the app or acceptance** — Task 4's mixdown path and Task 6's disk sink run with no device.
6. **Clipping or a frame stall** — Task 4 asserts peak ≤ 1.0 and Task 6 measures the 240-frame marginal.

- Consumes: the recon facts in the spec §6 and `.superpowers/sdd/s5-audio/recon-assets.md`.

- [ ] **Step 1: Write the SXDF carve script**

`tools/re/audio/s5_decode_gate.py`:
- Read the 0x60-byte header (`SXDF`/`SXDS`, version, size, hash, name).
- Walk chunks from `0x60` (`char[4] magic` + `u32 size`).
- Locate `WAVE`; for `music.sxd1` read record 0 (76 B: `+0x04` fmt, `+0x08` rate, `+0x14` frames, `+0x20` bytes, `+0x24` start) and carve from `music.sxd2` at its `SXDS` payload (`0x60 + start`, length `bytes`).
- For `boss01.sxd` carve one record per distinct format word (44/64-byte records; the builder check measured `0x00FF0121`, `0x00FF0142`, `0x00FF0221`, `0x00FF0242`, `0x00FF0642`); write the record's declared length/start and the DATA base.
- Write raw `.at9` and a minimal RIFF wrapper carrying the fmt word where the decoder needs it.

- [ ] **Step 2: Decode to WAV**

Try in order:
1. FFmpeg's `atrac9` decoder via the RIFF wrapper (build-time subprocess).
2. VGAudio's `At9`/`Atrac9` path in a tiny C# harness (MIT).
3. If both reject the config, read the bit split at the `Invalid ATRAC9 configure data` xref (`0x12B5660`, xref `0x98429E`) in `out/re/eboot.elf` and retry.

Expected: a 48 kHz WAV with the declared duration (Prologue = 10,898,874 samples ≈ 227.06 s; a boss01 record = its `frames/48000`).

- [ ] **Step 3: Verify non-silence and record the layout**

Run: `python3 tools/re/audio/s5_decode_gate.py --root "$SOTC_GAME_ROOT" --out out/s5/gate --check`
Expected: exit 0; every carved WAV has RMS > −60 dBFS, peak ≤ 1.0, duration within 50 ms of `frames/rate`, no NaN.

Write `docs/notes/s5-audio-recon.md` with: the header/chunk layout, the per-bank `WAVE` record layout (stride, field slots, partition check), the AT9 config word(s), the decoded channel count, and the exact decode command.
