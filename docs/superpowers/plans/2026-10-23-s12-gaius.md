# S12 Gaius Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the third colossus, Gaius (`colossus_03_knight`, tables `KNIGHT`), from the game's own exported behaviour graph and per-clip event tracks on his lake arena, with the stuck-sword climb, proven by a scripted selftest, an e2e run, goldens and a frozen acceptance chain.

**Architecture:** A stdlib-Python exporter turns `eboot.elf`'s mode tables into `sotc-scr-graph/0` JSON in the library; a C# `ObjAnimReader` writes `<glb>.events.json` sidecars; the app gains a strict, pure graph interpreter (`scr_graph.*`) fed by a per-frame `ScrWorld` view, an event consumer (`objanim_events.*`), band enable windows and a slope gate, and Gaius as an encounter table on `arena_03`. Five time-boxed RE gates (R1–R5) close the open decodes or select the design's named fallbacks.

**Tech Stack:** C++20, SDL3/SDL_GPU/Metal, doctest, .NET 10 + xUnit (BpConvert), Python 3 stdlib, bash 3.2, Ghidra headless.

**Spec:** `docs/superpowers/specs/2026-10-23-s12-gaius-design.md` — its §13 builder-check rulings are binding and override §§1–12 where they differ. Recon: `.superpowers/sdd/2026-10-23-s12-recon/{graph,knight,sword,objanim,arena03,render}/`.

## Global Constraints

- Frozen and never modified: `scripts/s3…s11-acceptance.sh`; every blessed golden for s3…s11 stays byte-identical (`git diff --stat <base> -- tools/verify/golden/` shows only `s12/` and `PIN`).
- Valus and Quadratus runtime paths unchanged (the user: Valus "Fix later"; Quadratus's migration is out of scope).
- No committed derived game data except small generated numeric tables on the `ride_points.h`/`quadratus_root.h` precedent: exported graphs, event sidecars, test fixtures sampled from game files and mesh vertices are generated into the library or the build directory.
- Windowed; the cursor is never captured. `caffeinate -dimsu` around every viewer/verify/acceptance run; GPU runs serial; never two runs sharing an `out/`.
- Bash 3.2; stdlib Python (run with `-I`); C++20; no new dependency; the game tree read-only; the converter's parsing stays behind its readers (no `AquaModelLibrary` types outside the adapter).
- A branch bakes into its library view (`make libview BRANCH=<name>`); the knight bake and the behaviour export are promoted to the base library at merge (S11 ruling A16 pattern).
- Every authored value carries a label (`authored`, `data <VA>`, `measured`, `R<n> decode`) in a comment; the results note tabulates them (§13.10).

## Review Focus

1. **A graph that uses something the interpreter does not know.** Loading must fail loudly, never silently skip a clause. Test: Task 4 `scr_graph_load` rejects an unknown predicate fn and an unknown action kind with the fn/kind in the error.
2. **The blade disabling under the player.** The player must fall or be carried, never stay standing on air or snap. Test: Task 7 `test_climb_window` — disable at 30 % (fall, no band) and at 70 % (carried onto the forearm band, position continuous within 0.5 m).
3. **His own damage hitting the climbing player.** `KNIGHT_ATK_SHOCK2` is live over the blade in `atk1_3`. Test: Task 8 `events_damage` returns no hit for a player whose `attachedTo`/`standingOn` is this entity.
4. **The slam tunnelling through the player.** The tip moves 350 m/s. Test: Task 8 a box moving 11.7 m in one frame across a stationary capsule is a hit (swept), and a box ending short of it is not.
5. **Gaius walking off his disc.** His graph never tests walkability. Test: Task 9 selftest line `s12-bound` asserts his root stays within 36 m of (−300, −1400) for the whole run, and a unit test clamps a goal outside the radius.
